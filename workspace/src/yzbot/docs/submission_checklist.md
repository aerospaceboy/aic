# 提交与赛前核对

- 按主办方最新要求准备源码、技术文档、录像和团队信息；规则原文件保留在根目录 `rules/`。
- 使用 `scripts/package_submission.py` 生成源码 ZIP，避免直接压缩整个开发目录。
- 解压后校验 `SHA256SUMS`，在 Ubuntu 22.04/Humble 环境重新构建并运行测试。
- 确认目标机器的图形桌面、Gazebo、RViz、CoStudio、coBridge 及网络正常。
- 配置当前用户的 API Key，确认正式模型解析成功。源码、录屏与提交包不得包含私有凭据。
- 一键启动输出 `MANUAL_PROBLEM_MODE=PASS` 后，提交题目与对应映射规则。
- 核验每件视觉目标、抓取结果、实际落区、五件完成且无跳过、总用时与安全状态。
- 按规则核对真实有效避障次数；未自然触发的指标不能补写为成功。
- 保留机器人模型、地图、场景、许可证、扩展构建产物和运行所需配置。
- 确认 ZIP 不含 Git 历史、AI 交接文档、历史验收/工作记录、备份场景、构建缓存和旧日志。

## 国赛预选赛专项核对

- 向主办方核实最终评分表。会议截图中技术文档为 20 分，二次整理指南标注为 10* 分，不能擅自据此计算总分。
- 获取并实际导入主办方指定的可视化布局；项目自定义 CoStudio 扩展不能直接视作官方布局。核对接口、版本、完整题目显示与实时刷新，保留实录。
- 同时展示正式题目的种子、计算题和映射规则，以及红色数量/区域、蓝色数量/区域。没有官方种子时补取原始出题输出，不伪造。
- 任务进度应正向增长；当前任务、当前状态、移动路径应对应本轮并持续更新。摄像头画面为辅助项；Gazebo 与要求的可视化窗口应同时清晰可见，RViz 可辅助展示。
- 检查初始 10 个物块的全部 45 对水平间距均不小于 2 米。A/B/C 任意两区之间应有主办方原地图已有墙体隔开；自加墙不能代替该证据。区域尺寸不得改变，压线放置按主办方口径核验。
- 动态障碍物应真实运动且实际影响本轮通行，至少有两个不同障碍的有效响应证据。仅远处巡逻不算；纯等待是否计分仍需最终规则确认，不能仅凭软件计数判定比赛得分。
- 录屏必须看清实际夹取、运输、释放与落区，五件逐件核对。按资料准备屏幕共享与操作人员/现场两个拍摄角度，具体会议安排等待主办方通知。
- 技术文档应由团队审阅原创性，填写真实队伍与成员信息，解释当前算法、实测收益及局限；不能把未通过的候选结果写成完整资格。
- 源码使用 ZIP；技术文档及视频按原格式单独放在提交文件夹外层，勿全部压成一个包。整个网盘目录按“编号-队伍名称-队长”命名并分享整个文件夹。附件中的示例不是本队编号，截止时间以正式通知为准。
