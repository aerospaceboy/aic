## 2. 这轮真正改变了什么

### 批量导航失败恢复

V8 声称“一次尝试后恢复串行”，但旧实现将队列恢复后又进入同一个批量分支；反馈还会裁掉原始锚点，动态倒车结束则重新发送批量动作。

- `nav_batch_attempted` 限定每个导航指令只尝试一次批量路径，失败后所有剩余阶段持续使用串行，指令结束后才重置。
- 原始锚点列表不再被 Nav2 的剩余数量反馈修改；反馈仅用于进度显示和现有进度窗口。
- 可选批量服务器未发现时立即走串行，不再阻塞执行器等待原有 120 秒发现预算。
- 批量发送同步异常、异步拒绝/错误、结果异常、abort、慢进度以及倒车恢复统一走串行恢复。
- 正常成功路线、严格 BT、出生双障碍串行段、速度与安全阈值保持原样。
- 新增 `test_navigation_batch_recovery.py`：在旧代码上 8 项全部失败，修复后通过；覆盖真正重新进入 dispatcher 后的行为，避免只测“队列恢复了”却漏测再次批量化。

### 计时证据

`speed_profile_recorder.py` 原来把采样间隔截为 0.5 秒，未报告丢失时间。现在新增 `timing_coverage`：采样覆盖墙钟、未观测墙钟、最大采样间隔、延迟采样次数。仍不使用一条旧速度推算长时间位移。该字段只增强诊断，不改变控制。

## 4. 全面审计后需要纠正的判断

### P0：最终真值与纯物理投放必须分开

`mybot/pick_place_moveit.py::run_place_only` 在释放后执行十次 `set_entity_pose`，再稳定物块。这是既有行为；“只纠正几毫米”写在注释里，但此段没有实际限制修正位移。最终精确真值可能是位置设置后的结果，不能据此声称纯物理放置达到同样精度。此次没有把这段变得更激进，也没有在未验证时删除它。

实施路径：

1. 在首次位置设置前记录物块真实位姿、预期槽位、三维误差、夹爪位姿和释放时间；同时保留释放后 0.2/0.5/1.0 秒轨迹。
2. 明确比赛是否允许任何位置修正，并把“原始物理误差”和“修正后误差”分成不同验收字段。
3. 若要求纯物理投放，在隔离实验里禁用位置设置，先优化底盘停靠、带载伸臂与开爪/脱附时序；分别测 A/B/C 五次连续投放。
4. 所有物块自然落稳且通过原有区域/精度边界后，才运行混色五物块。禁止仅检查被设置后的坐标来验收此优化。

### P1：选块代价模型比继续全局提速更值得做

当前 `cube_delivery_cost` 的入站路段主要是欧氏距离，另有历史地图表和经验惩罚；它不是当前严格锚点 Smac 路径的完整成本。`blue_C` 在不匹配历史起点表时还会重复叠加风险惩罚；`blue_B` 的出生五块特殊选择与强制原点计分也存在不一致。这些是审计发现，尚未据此修改实体顺序。

实施路径：

1. 在静态地图、当前 footprint、实际安全锚点和实际 approach side 下采集有向 `ComputePathThroughPoses` 路径长度及转角。缓存键至少含地图/配置哈希、起点区、物块、目标区和接近方向。
2. 使用成功日志估计入站、出站、带载、停靠与机械臂时间；把真实失败风险独立建模，避免成本表覆盖或重复惩罚。
3. 同色最多五个实体，枚举所需子集与顺序即可。保留题目颜色顺序，并加入切换到下一颜色首块的代价。不要只优化第一趟。
4. 离线对全部 48 题比较当前与候选选择，列出改变了顺序的题和预计节省；路线几何和安全参数不得随选块改变。
5. 先验证收益最大且高风险的一题，再验证反向颜色顺序，最后覆盖全部改变了顺序的题。

### P1：恢复的下一步是动作生命周期审计

本轮修复了确定性批量重试循环。下一步单独审计迟到的 goal response/result、取消期间任务切换和服务器失联：为每次发送保存 action 身份或 generation token；只有已确认旧动作停止后才能开始直接控制或新动作。先做故障注入，不要靠扩大超时掩盖竞态。

### P2：性能诊断不能把所有延迟归因于 VM

本轮基准 RTF 接近 1 仍用了 327.3 秒；蓝块 4 回 B 的导航为 40.10 秒，而历史约 23.41 秒。应逐段关联路径长度、控制器曲率、停转和安全限速，再定位差异。`distance_m` 当前是速度与采样墙钟的估计积分，不能当实际 Smac 路径长度；低 RTF 时尤其不能混用。

实施路径：为每次动作保存 `/plan` 路径长度、里程计时间戳积分、墙钟起止和采样覆盖率；固定题目做同机交替 A/B 至少三组，只有在相近 RTF、同样成功/安全结果下仍稳定节省才接受。

### P2：感知按需订阅仍是待证假设

保留 5 Hz RGB-D、激光和安全链。过去回调门控或降到 3 Hz 没有完成可靠五物块提速证明。若再研究，先量化退订后 Gazebo 是否停止渲染，以及重订到首张有效配对帧的延迟；清掉旧同步队列，保证新的 waiting_perception 不会使用前一轮图像。不要把仅仅跳过 OpenCV 等同于停止相机负载。

## 5. 保持的约束与交付方法

- 目标依次为完整合法任务、真实安全与投放、双障碍有效响应、墙钟 <300 秒。
- 保留真实墙体和安全锚点；禁止扩大通过半径、缩 footprint 或全局提速换成绩。
