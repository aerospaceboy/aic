# 运送策略优化与对照验证（2026-10-21）

本次优化针对默认分散物块布局，保留单件夹持、既有安全几何和放置验收。新增路线估价与安全边界重规划，同时保留原调度作为合法基准方案。不能把更低的模型代价直接当作实际提速。

## 实现

- `tools_demo/transport_routes.py`：将当前布局的取件绕行、配送绕行和离架引导抽成纯函数。导航器与估价器共用函数；旧布局导航分支保留。原有两次中心穿越、安全侧翼、出生区通道及红2重定位修复均保留。
- `tools_demo/transport_schedule.py`：分别估算空载导航、精确靠泊、离架、持物导航、抓放、离区和风险代价。按目的地区域的累计件数计算槽位与离区状态，最后一件不计离区。槽位间距计算与实际投放共用 `centered_slot_offset`，没有改变原间距。
- `tools_demo/unordered_schedule.py`：保留原API，扩展可选的状态转移、已有槽位数和必选实体约束。仍保证颜色/目的地需求和物块实体唯一性。
- `mission_coordinator.py`：任务开始先保留原DP生成的合法方案，再用新模型评估替换。成功离区、空载失败恢复离架后才重算剩余任务，已执行前缀和完成计数保持不变。抓放、验收和持物导航期间不重排当前货物。
- 导航状态携带中心小车的已验证响应、任务ID和仿真时钟纪元。协调器只接受当前任务、当前纪元的证据，不因“计划经过”就视为已经避障。
- 未取得中心响应且仍需蓝块时，候选计划保留尚未访问的蓝3交互路线。实体访问不是实际响应成功的证明；真实动态验收仍独立检查。
- 显式手动顺序、已加载的离线策略及强制颜色顺序优先。估价、配置或库存异常时保留合法基准/剩余方案，并记录原因。

没有调整巡航速度、底盘足迹、碰撞净距、机械臂参数或动态物体运动。

## 实测校准

`scripts/calibrate_transport_timings.py` 从受控完整日志提取成功导航段。当前随附 `config/transport_timing_profile.json` 使用本轮基准数据，共10个测量样本。该数量是导航段数量，不是10轮比赛。

出生区公共前缀单独计量，避免将公共通道的延迟仅归因于某一首件，进而错误偏爱没有测过的候选。样本较少时与几何先验混合，不用单次最快值替代估价。仅在起点接近、朝向接近、航点数量和坐标形状匹配时应用测量。

校准表校验导航数学函数、共享路线、导航器、布局参数、风险路线、Nav2参数和任务参数的SHA256。部署不一致时拒绝旧测量并记录日志。需要有匹配布局、来源可核对的新日志后才能重新校准，不能仅为消除拒绝提示而重新签名旧地图日志。

空载/持物有效速度和抓放时间仍包含先验；当前模型没有调用Nav2对每一对候选求完整全局路径，也没有精确预测远期障碍相位。因此它仍是带风险惩罚的估价，不是物理最短时间证明。

## 为什么默认使用8秒收益门槛

第一版模型将 `3红→B、2蓝→A` 改为：

`蓝3→A、红2→B、红4→B、蓝1西侧→A、红3→B`。

模型认为它比原方案约好4.6秒，但实际对照没有提速。因此最终实现先生成原合法方案，再比较新方案；初始及在线替换都需预计收益至少8秒。较小差异只记录 `transport_replan_hold`，不更换方案。8秒是本次工程保守门槛，不代表已建立统计显著性或所有任务的统一误差界。

默认参数：

```yaml
transport_schedule_enabled: true
transport_replan_minimum_gain_sec: 8.0
transport_uncertainty_weight: 0.15
transport_timing_profile_file: transport_timing_profile.json
```

将 `transport_schedule_enabled` 设为false可使用原联合DP调度。改变相关配置后，校准表可能按设计被拒绝；比较时应记录实际运行参数。

## 当前限制

当前实测只覆盖一个五件任务的策略对照，不能证明全部合法任务更快或都在300秒内。动态相位和恢复会造成明显波动；基准轮未取得出生区原障碍对的完整响应，不能标为完整比赛验收通过。第一候选轮四个障碍响应齐全，但比基准慢，证据保留。

后续应在同一源码和配置下，扩展三条映射规则、已有慢题及多个动态相位，再根据预测误差调整门槛与校准覆盖。未完成的动态响应仍需独立验证，规划访问不能替代证据。
