# 视觉抓取修复记录（2026-10-21）

## 结论

当前已开启 `require_perception: true`，扫描改为与抓取相同的朝下姿态，
识别后保持该关节分支，高位对准视觉目标并竖直下降，不再先回竖直。
验收与历史失败轮次见 [视觉抓取验收记录](VISION_GRASP_VALIDATION_20261021.md)。
下文保留检测器修复时的原始证据与当时的阻塞原因。

## 根因（三个叠加）

1. **RGB-D 配对被时间戳差全部丢弃。** 任务运行时深度帧比彩色帧晚整整一个
   相机周期（0.250 s），旧代码把"最新彩色+最新深度"直接配对，每次都超
   0.12 s 容差；改成保留最近 8 帧、按时间戳找最近配对后恢复。
2. **BEST_EFFORT 图像订阅在这台机器上收不到帧。** 相机以 RELIABLE 发布，
   检测器用 `qos_profile_sensor_data`（BEST_EFFORT）订阅时实测常收到 0 帧
   （心跳正常、帧计数为 0）；改成深度 5 的 RELIABLE 后稳定 4.9–5.1 Hz。
3. **旧管线会整机卡死。** `message_filters` 同步回调里做阻塞 TF 查询，
   曾观察到进程 36 线程挂在 futex、心跳也停；改为独立订阅 + 定时器配对 +
   只查最新变换（timeout 0），不再有阻塞路径。

## 验证证据

- 独立实例：4.4–4.9 Hz 连续发布。
- 任务栈内实例：4.9–5.1 Hz（修复前 0–1 Hz，只有心跳）。
- VIS3 轮：日志出现 **13 次 `selected_target`、0 次 slot 兜底**，选中的坐标
  `(0.354, 0.014, 0.026)` 与真值货位一致——说明视觉已经真正驱动物体选择。
- 新增 6 项契约测试；全量 1574 项通过。

## 历史阻塞：强制视觉与取件"平面起始位姿"守卫冲突

打开 `require_perception: true` 后，取件在 `move_pick_approach` 立即被拒：
`pick_approach_rejected: unsafe starting pose for plane alignment`。
冻结轮次（R1）同一守卫 5 次全部通过、0 次拒绝；开着强制视觉的 VIS3 是
1 次通过、12 次拒绝。差异在于感知路径每次取件前都会做扫描摆位，随后
再取件的起始位姿不满足守卫的 `tool.z >= 0.25` / `joint1≈yaw` 条件。
最初通过安全高位复位解决；后来按用户要求，将平面对齐与抓取关节分支
前置到扫描阶段，取消识别后的竖直复位。异常起始恢复仅用于扫描前或旧模式，
视觉取件仍严格检查起始高度、平面、笛卡尔轨迹和实际到位状态。

## 当前状态

`require_perception: true`，`perception_timeout_sec: 1.5`，
`perception_recovery_rescans: 1`。禁止缓存货位快捷取件、感知失败货位兜底，
以及将视觉坐标替换为临近货位坐标；Gazebo 真值抓取校验继续保留。
