## 4. 汇总后集中做小修与补跑

每题检查 `result.log`、`audit.json`、launch 中抓取/投放事件和真值记录。**COMPLETED 只依据 runner 标记，不代替 audit 的顺序、真值和安全复核。**即使目录标成完成，只要 `motion_functional_pass=false` 就列入失败；耗时超 300 单列。取最新同版本 attempt，同时保留首跑失败，不用旧成功压住新失败。

先分类：启动/DDS/控制器竞态、STALE_SIM、运动导航失败、抓取/释放失败、顺序/真值错误、动态避障缺证据、净空不足/接触、motion 超时。不得把所有失败都归为“偶发”。已有旧风险只是排查线索，不能直接当新失败根因。

允许的小修：明确的话题或参数接线错误、解析/汇总字段错误、启动等待/就绪检查、断点目录、进程退出等待、局部状态机条件或有界恢复 bug。一次只改一个根因；修后运行相关测试，定向重跑失败题并回归一题相关的已过题。要宣称随机失败解决，至少再通过一次复现题。

禁止扩展为地图重布局、新的全局规划算法、新安全控制架构、大范围速度/机械臂调参、API 更换或 UI 重做。如果证据显示需要这种改造，记录问题、影响题目、复现命令和建议，作为未完成项交付；本轮不要自行展开。
