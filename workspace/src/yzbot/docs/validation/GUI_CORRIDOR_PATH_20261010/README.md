## 实时路径显示

在现有 CoStudio 三维地图上增加两条线，无需额外启动节点：

- 黄色 `navigation/planned`：当前 Nav2 全局规划 `/plan`，随着目标和重规划更新；3 秒无新规划或任务进入终态时清除。
- 青色 `navigation/traveled`：小车实际行驶轨迹，使用 Gazebo 实体位置，最多最近 1500 点；新任务自动清空，瞬移和数据中断后不串接旧轨迹。

场景最多 5 Hz 刷新；移动不足 0.06 m 不追加轨迹点，规划最多 1000 点并保留终点。路径随 `/competition/scene_markers` 完整快照发布，避免被旧场景 DELETEALL 删除。仅作为展示，不向导航或速度控制反馈真值。

在 CoStudio 现有连接上打开三维地图，固定坐标系选 `map`，开启 `/competition/map` 和 `/competition/scene_markers`。已有布局的 scene_markers 已开启，新路径会自动显示。若隐藏过标记，在 namespaces 中开启 `navigation/planned`、`navigation/traveled`。新版布局隐藏重复 `/plan`；局部路线 `/local_plan` 可按需关闭。

本轮确认 ROS 路径数据持续更新、实际轨迹终点相对同帧机器人位置误差小于 0.06 m，并从桥接日志确认真实 CoStudio 客户端订阅场景话题；没有采集客户端渲染截图，不能把这些检查写成已完成人工视觉验收。

## 计时和安全证据边界

运动时间由 mission 状态给出；HTTP 提交至终态观察时间含本次 API 和轮询误差，不含题目生成、系统启动及裁判现场展示。有效回放使用上一轮用户题目，未启动官方出题程序重新生成题目。解析沿用私有环境中的 qwen3.8-max，不修改/复制密钥。

动态安全指标覆盖四移动体，不能证明对所有静态墙均无接触。`collision ahead` 是控制器预测，不是实体碰撞计数；Gazebo contacts 尚未确认有源发布者，空输出不能证明无接触。辅助导航圆检查在早期候选 Wall_75 端点发现约 0.061 m 重叠，导航圆不同于实体碰撞形状，不能当作已确认撞墙，也不能据此宣称问题排除。

## 启动与查看

VM 上部署已更新，当前示例结束后保留 GUI 便于查看最终轨迹。需要重开全系统时执行：

```bash
source /opt/ros/humble/setup.bash
source $WORKSPACE/install/setup.bash
cd $WORKSPACE/src/yzbot
YZBOT_GAZEBO_GUI_RENDER_RATE=60 \
COSTUDIO_HEADLESS=False COSTUDIO_DEBUG_GUI=True \
COSTUDIO_RVIZ=True COSTUDIO_DASHBOARD=True \
COSTUDIO_CAMERA_STREAMS=True COSTUDIO_SLAM_EVIDENCE=True \
bash tools_demo/scripts/start_manual_problem_mode.sh
```

等待 `MANUAL_PROBLEM_MODE=PASS`，再在 CoStudio“题目与大模型解析”面板输入官方格式算术题和映射规则。CoStudio 地址 `ws://<VM_IP>:21274`，状态页面 `http://<VM_IP>:8080`。正在执行任务时不要重复启动，它会重建场景。
