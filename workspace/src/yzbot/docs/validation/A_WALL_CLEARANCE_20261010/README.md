# 五蓝撞墙修复与验证报告

## 结论

五蓝→A 在修复版本 `3e65e8caf684c687fe97952c344422863d7778a0` 上完成一次可见仿真验证：5/5、零跳过，5 次投放均为 valid+precise，真实 API 解析数量符合题目要求。运动计时 **293.9 秒**，HTTP 提交至任务终态观察 **295.662 秒**。通过本次撞墙专项检查及 300 秒运动门槛，**未达到 290 秒门槛**，也不是 48 题验收或多次稳定性证明。

Gazebo 物理接触观察器接收 149496 帧 contacts 消息，墙体接触记录为 **0**；四个移动体在线，原始两个移动体均记录 yield，动态碰撞判定 false，最小动态表面净空 **0.5122 米**。1466 个 Gazebo 真值姿态样本中，最大绝对 roll **0.155°**、pitch **0.119°**，未复现此前严重侧倾。

## 根因与修复

此前五蓝完成任务的结果，只证明投放和动态监测通过。旧 bag 的 A 区东侧墙尖附近出现严重侧倾，而动态监测不能识别所有静态墙接触。第一轮带物理 contacts 的候选验证又明确记录到 Wall_75 与腕部相机、轮子、机械臂接触，证明仅使用底盘圆形近似判断空间不足以覆盖携带姿态。

实际墙几何应取世界文件 saved state 的 link 世界位姿，再叠加 collision 的局部位姿；不能直接使用 model 初始 pose。检查还发现 NavigateThroughPoses 批处理会把这些阶段的限速重置为 0，并绕过逐航点的紧交接。

修复只作用于从南侧向当前 A 停靠点运输的路线：

| 场景 / 阶段 | 新路线或控制 |
|---|---|
| 通常从南向 A | 经 `(-2.10,-0.30)`、`(-2.10,1.85)` 绕开 A 东侧墙尖 |
| 西南方携带进入 | 先经 `(-4.25,-7.15)`、`(-2.10,-7.15)` 绕开 Wall_75 南端，再接上前述路线 |
| B bay 出发 | 保留原有 lower-east corridor，再加入 A 侧绕行，避免用新锚点替换旧安全出口 |
| 航点交接 | A_WALL 阶段逐点执行，交接距离 0.08m，不使用批量执行 |
| 速度 | 西侧接近 0.8m/s，长南侧接近 1.2m/s，两个墙尖阶段 0.6m/s，其他阶段恢复原速度 |

长接近段初版限速为 0.8m/s，安全验证耗时 302.5s；最终仅将该长接近段提高到 1.2m/s，墙尖限速不变。本轮没有修改布局、物块、区域、障碍轨迹、Nav2 footprint、安全阈值、载荷滤波、API 配置或解析校验。

## 尚未闭环

1. **托盘接触仍存在**：A-5 contacts 记录相机/轮子与取件托盘接触，另有正常夹爪抓取接触。当前专项不能宣称所有部件零接触。后续应分别定位非夹爪接触的时间、深度、进坞姿态和底盘速度，再修正停靠偏置或抓取姿态，不能过滤这些接触来验收。
2. **A-4 启动就绪失败**：发布者在线不等于有可用代价图。需核对非空栅格与导航生命周期，并检查等待就绪失败时是否携带正确 zone 返回给协调器，防止协调器无限等待。尚未证明具体根因，未改此逻辑。
3. **290 秒和完整赛程未验证**：本轮仅完成一个最终五蓝单色实例；其他混色任务、五红回归、48 题和全赛程计时均未重跑。不可沿用旧版本 48/48 结论覆盖本次路线修改。
4. 姿态统计来自约 5Hz 真值采样；圆形距离只是几何筛查，不能替代机器人全外形或实际物理接触证据。
