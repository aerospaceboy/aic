# 审查报告：3 red→A、2 blue→B 300秒基线优化

## 结论与口径

本轮完成用户授权范围内的布局联动与导航/选择修复，目标题在最终方案下两次达到运动300秒以内：**205.4s、190.3s**，均5/5、零跳过、颜色顺序正确、投放真值precise、安全门通过、两个原始移动障碍各有yield响应，最小动态净空分别0.3850m、0.3683m。此前同题516.9s。

这是两次物理仿真的运动基线，不是全48题稳定性证明，也不包含出题、真实API、CoStudio显示和完整比赛起止时间。完整比赛墙钟仍待验收。四个移动体均持续运行且被监测；本轮目标两次仅原始两体有响应，不写成“四个都yield”。

反向回归 **2 blue→B, 3 red→A：229.3s、5/5、零跳过、safe、min0.3593m**，但缺obstacle_2响应，CASE_ACCEPTED=false。它验证了B湾返回A的导航与抓放，同时暴露“首腿穿越失败→重试丢展示队列”的验收缺口；没有把它记为全门通过。

## 已证实问题和修复

### 1. 布局导致长距离、口袋出入和过时导航规则

四个物块及A区搬到有停车空间的区域；其托盘底座同步搬移：

|实体|原中心XY|现中心XY|
|---|---|---|
|red1|(-6.5,3.4)|(-3.0,3.8)|
|red3|(-11.5,-2.3)|(0.0,3.8)|
|blue1|(-10.5,2.3)|(11.8,-2.5)|
|blue4|(4.3,-5.4)|(12.0,-6.6)|
|A区|(-13.0,3.2)|(-5.4,3.8)|

A区东停靠=(-5.0,3.8,π)。B/C、其他6个物块、固定隔墙、岩石、四个移动障碍定义与保存状态不动。

同步world、托盘、complex_layout、final_mission_layout、mission/zones、协调器实体槽位、导航默认入口/停靠、地图、风险区和合同断言。此前canonical布局仍标red west+east、运行时却限制east；本轮将canonical allowed_sides同步为实际east-only，避免重新生成时复活未验证的west侧。

旧A_sweep/备用路线加旧A位置条件，防止新A仍绕到西端。旧布局证书归为历史，不用旧通过证明新布局。

### 2. 关闭旧评分开关后，基础评分仍使用旧区域坐标

cube_delivery_cost内部仍通过ZONE_ROUTE_APPROACH估计送达距离和方向，导致新布局第一轮蓝块选择不合理。新增use_legacy_route_estimate开关，并在协调器两处实体/接近侧选择中传入现行use_legacy_selection_costs。

当前模式使用真实目标中心做距离与转向评分；历史模式保持默认行为。该评分仍是启发式，不是墙体约束下的精确路径成本，也不保证C族最优。最终目标题实体顺序red1、red3、red2、blue1、blue4，题目颜色顺序未改变。

### 3. 在整周期都没有通行窗口的位置等待

r2机器人停在y≈-0.445；原障碍2的巡逻Y区间约[-0.8,0.1]，即使摆到最远端，与路径的侧向间距仍不足0.60m准入条件。连续等待8秒/重试同一路线无法解决。

新增lower_east_corridor_waypoints，仅对指定左上↔右下转移引导到(4.4,-2.5)，B湾进出需要时再经(13.4,-2.5)。绕开无窗口车道，不关闭原移动障碍，也不放宽安全准入；出生展示/实际响应路径仍保留。此修复不是通用“卡住就换路”，其他卡停仍需识别来源。

### 4. 红块走廊停车/旋转振荡

r2 red2→A约57.97s，导航指令约81%零线速，路径存在反复旋转/推进；不是安全层把正常前进指令截成零那么简单。

RPP预瞄min/max/time从.35/.85/.55调至.60/1.20/.80，内层rotate-to-heading关闭，由既有外层RotationShim负责朝向交接。巡航1.65m/s、碰撞预测、膨胀、安全门和footprint未放宽。

r3 red2→A约9.94s，red3→A约5.91s。总成绩来自布局、评分与导航配合，不能把全部收益归到单一参数。新布局其他窄路/反向/C族仍须全分布验证。

### 5. 致命起点编码和负边界索引错误

导航器订阅nav_msgs/OccupancyGrid，旧判断>=253把内部原始代价值误用于int8消息，永远不触发。现仅cost==100判为致命起点；99为内接膨胀、-1未知，不把71/99直接当成需要倒车的证据。负坐标索引改math.floor，防止边界外点被int截到0。

这一修复没有扩大恢复次数或在未知后方盲目倒车。仍通过既有碰撞检查和有界恢复执行脱困。
