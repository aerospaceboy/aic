## 路线验证

五蓝使用最终修正版展示节点：1271个快照，800个含规划线；520个快照的规划年龄超过3秒，最长22.44秒仍保持显示。267个导航已结束快照中，残留黄线为0；最终黄线清除、657点青色轨迹保留。实测宽度分别0.14/0.035m，轨迹终点采样误差最大0.05915m，小于0.06m门限。

五红展示了1267个快照，规划最长29.70秒持续显示；其导航状态订阅在该题结束后生效修正，不能用五红证据证明逐目标清除已通过。逐目标清除由五蓝的实际状态事件验证。

五红开始后，实时ROS图核对发现最初接入的 `/competition/navigation/status` 没有发布者。已改为真实 `/competition/navigation/state` 并重建，五蓝新场景使用修正后的展示节点。五红搬运过程中没有改导航、安全链、机械臂或任务代码；其旧展示进程持续到该题结束。因此不能把两题宣称为同一冻结展示构建。两个任务的搬运控制代码一致。

五蓝初次API预检失败，模型回复计数不满足合法范围，任务没有启动；原始回复未记录，不能确定是0或其他非法数值。使用常规变量映射再次提交算术题后，经真实API和严格验算接受。没有修改解析验证器或开启确定性降级绕过API。失败记录保留。

单元与构建检查：构建成功、749 passed / 3 deselected；路径代码和测试flake8通过。未改地图、物块、区域、动态障碍、安全阈值或速度控制参数。

## 查看方式

CoStudio连接 `ws://<VM_IP>:21274`，三维地图固定坐标系选`map`，开启 `/competition/map` 和 `/competition/scene_markers`。`navigation/planned`是粗黄线，`navigation/traveled`是细青线。任务结束后黄线消失，青线保留；提交下一道题后轨迹重置。

当前测试结束后保留最后一题的Gazebo/RViz/CoStudio运行环境，不追加第三题。单次任务验证和ROS数据检查不能替代人工确认客户端最终渲染；四移动体安全监测也不能单独证明所有静态墙都无接触。

完整日志、bag及各轮版本补丁留在VM `$RUN_ROOT/`。两处用户未提交的GUI/支撑轮TF修改继续保留，提交只到master。

## 后续静态墙复核与修复

旧五蓝结果的动态安全判据不能证明静态墙无接触。后续 bag 发现 A 区墙尖附近严重侧倾，并由候选轮 Gazebo physics contacts 实证 Wall_75 接触。已通过南侧绕行与逐航点限速修复，最终五蓝一次 293.9s、墙接触0，未达290秒；取件托盘非夹爪接触仍需单独处理。详见 [撞墙修复报告](../A_WALL_CLEARANCE_20261010/README.md)，不能把旧报告作为全机器人零碰撞证明。
