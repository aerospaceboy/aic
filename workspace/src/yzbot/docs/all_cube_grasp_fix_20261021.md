# 全部物块的抓取平面保护与验证（2026-10-21）

## 范围与实现

覆盖 red_cube_1～5、blue_cube_1～5，以及 mission.yaml 当前允许的全部 13 个
抓取方向。正常任务和旧版循环均通过公共 move_pick_approach()，不会按物块名称
选择无约束的接近路径。此前的公共接近修复继续使用前伸弯曲 IK 种子、拒绝反向
肩腕解、必要时高处对齐，并约束 joint1/joint4/joint6 在目标垂直平面内运动。

本次将公共保护延伸至最终竖直下降，包括失败后的下降重试：

- GetCartesianPath 请求加入目标平面的关节约束，沿用 ±0.020 rad 范围。
- 执行前逐点检查返回轨迹，拒绝缺失反馈、非有限值，以及肩腕侧转超限。
  使用绝对关节角比较，连额外整圈旋转也不接受；只检查终点无法覆盖这些情况。
- 任何点不满足条件，即拒绝执行；原有终点真实姿态检查、竖直下降检查、抓取
  窗口和夹指离面间隙保护继续生效，不增加自由关节空间下降回退。
- 接近平面日志带上 cube 名称，便于按物块核对实际任务。

这项下降检查是补充保护，不代表旧日志已经证明下降阶段发生过同样的分支翻转。
历史明确的风险链仍是归零竖直姿态 → 缓存货位跳过扫描 → 接近时选择反向逆解。
工具由朝上转成朝下的正常俯仰仍在目标平面内完成。

## Gazebo 实际抓取

证据目录：`runs/all-cube-grasp-20261021/`。

这是分货位的抓取专项测试：Gazebo 与 RViz2 打开，测试开始前把小车初始化到
对应的正常停靠位置，加入 15 mm 横向偏差；每项从归零竖直机械臂开始，调用
生产代码 run_pick_only()，实际完成接近、高度标定、竖直下降、闭合、抓取窗口
验证、附着、缩回和携带包络验证。阶段内没有为通过检查移动物块或改写目标姿态。
每项完成并记录结果后，才执行诊断清理和场景复位。

此流程直接加载最终源码，独立运行于空闲任务系统；源码与最终安装执行文件的
哈希在 final-build-receipt.json 中相同，且与实际测试的源码哈希一致。初始安装
文件哈希和场景初始化范围保留在 source-receipt.json 中。

这不是包含导航、解析及交付的整轮竞赛验收，也没有延长任务时限或放宽安全窗口。
