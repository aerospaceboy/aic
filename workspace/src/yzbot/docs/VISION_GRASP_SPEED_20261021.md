# 视觉抓取适度提速（2026-10-21）

## 耗时来源

基线为 `880b430` 的 VIS7-DIRECT-A/B，两轮十件从 `scan_started` 到
`gripper=closed_clearance` 平均 7.590 s，其中扫描摆位 3.572 s、扫描就绪后
等待选中目标 0.090 s、选中目标到闭合 3.927 s。图像识别延迟不是主要瓶颈。
MoveGroup 速度和加速度倍率已经是 1.0，不能继续提高该倍率。

## 改动范围

- 扫描点由 `[0.300, -0.030, 0.320]` 改为 `[0.330, 0, 0.300]`，
  保持朝下姿态与正向抓取关节分支。正前方扫描消除从竖直零位出发的
  单独侧向对齐，稍低且靠近抓取点的位置减少后续横向和竖直距离。
- 仅空载视觉抓取的高位横向移动、下降到安全点采用 0.45 s、0.90 s
  目标时长。贴近物块的最终下降仍为 0.60 s，夹爪、携物收臂、放置及
  视觉来源策略不变。
- 对上述两段轨迹使用 0.95 rad/s 的关节段速度上限，低于 URDF 的
  1.0 rad/s。重新计时后按每个关节、每对相邻轨迹点计算速度；超限时
  按统一比例延长整个轨迹，保留路径、平滑时序和全部末端目标。
  因此 0.90 s 是期望值，长轨迹实际可以更慢，避免强行缩时超速。
- 原平面守卫、最低对齐高度 0.250 m、碰撞检查、横向/朝向/高度到位
  校验及 Gazebo 真值校验均保留。识别后仍直接下降，不恢复竖直。

## 验证

构建 mybot/tools_demo 通过；完整非 linter 测试在独立 ROS_DOMAIN_ID=219
运行，1686 passed、3 deselected。新增测试验证非均匀多关节轨迹缩时后
保留全部路径点、速度受限、非法速度拒绝，以及贴近物块阶段保持原时长。
四个本次相关 Python 实现/测试文件通过 ament_flake8。

仿真沿用原 one_round.sh 与规则2，启动 Gazebo、RViz，真实 LLM 解析。
使用被动观察器保存视觉选中目标、操作请求/结果、源码收据、终态两次
Gazebo 真值；与前一版本相同的完整验收合同用于结果判定。
阶段耗时取实际日志时间戳，单独比较扫描到夹爪闭合，避免整轮导航波动
被误计为机械臂提速。

## 实测结果

VIS8-SPEED-A（task `freeze-VIS8-SPEED-A-477c3625c8`）完整验收通过：
5/5、零跳过、258.783 s。五次 `selected_target`、五次成功视觉取件，
无货位/缓存兜底、无识别后复位、无平面起始拒绝；十段竖直下降检查、
终态两次采样共十项落区真值检查全部通过。无碰撞，最小动态间距
0.7221 m，自然响应两个出生点移动障碍物，原避障验收合同通过。
源码收据全部匹配，检测器实现未改动。

| 每件平均实测阶段 | 原版两轮十件 | 提速版五件 |
| --- | ---: | ---: |

收益主要来自减少扫描摆位的侧向对齐；较长的横向或下降轨迹受到
0.95 rad/s 上限约束，实际时长会大于目标值，不能按配置目标声称
所有下降都提速。相机约 4 Hz 的帧到达相位也会影响本轮识别延迟。
全轮时间另受导航避障影响，不能全部归因于机械臂。
