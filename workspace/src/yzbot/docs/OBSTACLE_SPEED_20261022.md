# 起点双障碍物优化分析与更正（2026-10-22）

## 结论先行

**上一轮“两项都是真实响应”的结论不成立。** 最终完整轮的 `spawn_avoidance_1` 记录发生在机器人停在 `obstacle_2` 等待点时：

- 时间：导航开始后 19.315 秒
- 机器人：`x=6.691, y=0.525, speed=0.242→0`
- `obstacle_1`：`y=-0.174`，距离约 1.81 米
- 当时 `obstacle_2` 即将在 19.38 秒开始另一个等待

这是 `response_distance=2.00` 造成的交叉计数，不是机器人为了避让 `obstacle_1` 发生的减速。把窗口收回到 1.5 米后，`obstacle_1` 不再触发；恢复到原始的 1.30 米 / 0.80 m/s 后同样不触发。因此目前只有 `obstacle_2` 是真实有效响应。

相关的 `validation-summary.json` 和此前完整轮的双响应结论已作废，不应作为验收依据。

## 仍然有效的改动

- 周期从 11.2 秒缩短到 10.181818 秒，速度 0.25→**0.275 m/s**；Y 行程仍为 `[-0.80, 0.60]`。
- 新增任务开始时重置相位（`reset_phase_on_plan` / `mission_phase_offset_sec`），启动时仍使用原 `phase_offset_sec`，世界初始姿态契约不变。
- `obstacle_1` 任务相位 3.54 秒，`obstacle_2` 任务相位 0.29 秒；第一个等待从约 10 秒降到约 0.9 秒，第二项真实响应在最终轮约 29.2 秒 / 起点探针约 31.2 秒。
- 响应判定已恢复原始 `obstacle_1: 1.30 m / 0.80 m/s`，没有保留放宽的阈值。

## 还能不能继续优化

### 1. 单纯继续提高速度：空间很小

0.275 m/s 是在当前 **10 Hz 真值、全相位连续两帧可放行**约束下选出的最大值。提高到 0.30 m/s 后，等待位 `(9.84, 0.51)` 等位置已经不存在连续两帧可放行窗口，针对性准入测试失败。继续提速会缩短安全窗口，不能只靠调 `period_sec` 完成。

要把速度继续提高，需要先改采样/控制频率（例如 20 Hz）或改路径/等待位，并重新证明全相位窗口；这不是一个只改常量的优化。

### 2. `obstacle_2` 的相位还有明显空间

最终轮第二项等待：

- 开始 19.381 秒
- 结束 27.934 秒
- 持续 **8.55 秒**
- 真实响应在 29.234 秒

这 8.5 秒等待主要来自 `obstacle_2` 相位，不是速度不足。改变任务相位、让它在底盘到达 `x≈6.68` 时更接近可放行状态，有机会把第二项响应提前数秒。建议只针对 `obstacle_2` 做相位扫描，每次记录等待时间和真实响应，不修改 `obstacle_1` 的阈值。

### 3. `obstacle_1` 要变成真实响应，必须改机制

当前物理路线是“底盘先停在 `obstacle_1` 前方约 1.35 米的等待点”，接近速度只有约 0.35～0.70 m/s，之后才放行。原始响应要求是 1.30 米内峰值 ≥0.95 m/s、降到 ≤0.80 m/s，因此：

- 等待点附近永远达不到 0.95 m/s 峰值；
- 放行后底盘会快速通过，但 `obstacle_1` 已经在车道下方；
- 把窗口扩大只是把 `obstacle_2` 的停车错误归因给 `obstacle_1`，不是修复。

可选的真正修复方向：

1. **按“谁导致停车”记录响应**：当任务导航因 `mover_crossing_hold`/`obstacle_1` 实际停车，并经过安全窗口后再放行，直接记录一次 yield。需要改证据链路和测试，不能只改速度。
2. **改变等待点/接近速度**：让底盘在 `obstacle_1` 前方以 ≥0.95 m/s 接近并真实减速；必须重新证明刹车距离、静态地图和动态碰撞安全。
3. **改变 `obstacle_1` 轨迹/任务相位**：让它在底盘通过时仍在 1.3 米内进入车道；当前准入模型只允许很窄的下降相位，直接调相位无法同时满足安全和响应。
4. **独立设置两个障碍物速度**：`obstacle_2` 的安全窗口比 `obstacle_1` 宽，单独提高它的速度可能减少第二项等待；但仍不能解决 `obstacle_1` 的证据问题，且需要把单一 `CORRIDOR_PATROL_SPEED` 拆成每个 actor 的速度契约并补测试。

### 4. 对整轮时间的影响有限

最终完整轮 267.795 秒，两个起点等待合计约 9.45 秒（0.9 + 8.55）。即使把第二项等待压到 2～3 秒，整轮大约只能省几秒；主要时间仍在取件/运送导航和机械臂动作。继续优化应优先 `obstacle_2` 相位，而不是继续提高全局速度。

## 推荐下一步

先只做一件事：保持原始 1.30/0.80 响应口径，扫描 `obstacle_2` 的任务相位，目标是把第二项等待从 8.55 秒压低，并确认真实 `spawn_avoidance_2` 提前。`obstacle_1` 需要单独决定是否改证据归因或改等待路线；在未做这两项之前，不能宣称已获得两个真实起点响应。
