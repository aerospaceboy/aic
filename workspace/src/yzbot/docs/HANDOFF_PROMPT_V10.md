# ROS2 竞赛接手提示词 V10：保持题目颜色顺序，继续冲刺 300 秒

更新时间：2026-09-05 晚间审计。本文提供工程事实、验证边界与实施建议，不代替用户的新指令。V8/V9 和下午记录保留作历史；当前入口是本文与 `docs/validation/ORDER_AUDIT_20260905/`。

## 1. 交给下一位 agent 的任务

先理解、复现，再持续修复和优化；不要因为某一道题低于 300 秒就结束。目标是合法题目范围内，完整五物块、零跳过、按题目规定的颜色与目的地顺序抓取和投放，在真实安全链下稳定完成，并把完整比赛墙钟压到 300 秒以内。阶段性运动测试通过后，仍须覆盖出题、大模型、展示与评分全过程。遇到失败要定位、修复、复测；只有达标证据足够，或确实需要用户/外部环境解除阻塞时才交还，并明确剩余工作。不要用一条提示词承诺跨会话无限运行；每次交接留下可恢复的实验状态。

用户于本轮明确澄清：**“只约束题目颜色顺序，同色实体可优化”。**

例如 `4 red -> B, 1 blue -> A`，允许优化四个红色实体的选择、顺序及合法接近侧；必须先完成这四个红色任务，再执行蓝色。不可把题目归并成固定蓝先红后；不可挪动投放目的地；不可把同色实体编号误当成用户要求的固定顺序。DP 功能继续保留并使用，无需为了规则关闭所有选块优化。

## 2. 我对项目的理解

这是 ROS 2 Humble + Gazebo + Nav2 + MoveIt 的完整竞赛系统。任务不是简单的点到点导航：题目先生成有序的颜色、数量、区域任务，解析器产出 TaskPlan，MissionStateMachine 展开逻辑作业；coordinator 在当前逻辑作业允许的同色实体里选块，task_navigator 通过安全锚点、接近侧、最终停靠与退出阶段运动，机械臂抓放后由 Gazebo 真值检查投放，动态障碍与 Collision Monitor 持续约束速度。任何优化都必须保留这条因果链。

主要位置：

- VM 工作区 `/home/ros/dev_ws`；权威仓库 `/home/ros/dev_ws/src/yzbot`，master，远端 `cty050422/yzbot-224`。复用已有 SSH 配置，不在仓库写密码、密钥。
- `tools_demo/tools_demo/task_protocol.py`、`task_parser_node.py`：结构化任务及大模型输入。
- `mission_state_machine.py`、`mission_coordinator.py`：逻辑顺序、实体选择、重试、投放验证。
- `pick_order_policy.py`、`config/cube_order_policy.json`：按实际有序任务查表，并校验完整实体序列。
- `task_navigator.py`、`navigation_math.py`、`bot_navigation/config/`：路线、停靠、退出与安全参数。
- `mybot/mybot/pick_place_moveit.py`：抓放和既有位置稳定逻辑，实际路径以 `rg --files` 确认为准。
- `speed_profile_recorder.py`、`competition_case_runner.py`、新 `evidence_audit.py`：计时与证据；runner 的 CASE_ACCEPTED 不是完整比赛达标。

项目目前的瓶颈主要是长距离空载/带载转运、保守但必要的绕行、不同接近侧的停靠与出口成本，以及重试造成的长尾。单独提高速度或减小碰撞边界不能解决路线和动作生命周期错误。离线 DP 是合理方向，但成本必须覆盖“上次实际投放槽位/退出侧 -> 下一物块 -> 本次投放侧”，否则一个局部便宜的选择可能把后续代价放大。

工作区的竞赛资料目录含 `2026/大模型技术创新赛比赛规则2026.pdf`。本轮阅读到第 4 页规定每轮五分钟、计时后生成题目并给出资源抓取顺序；第 6 页要求按大模型规则抓取放置。PDF 没有明确同色实体编号，本轮以上述用户澄清确定实施语义。地图文件更新说明与出题程序说明也应一起复核，不能仅凭旧 agent 的结论认定全面合规。

## 4. 本轮纠正了什么

本轮起点为 `75d9f58d6fe2af465f3a3a165a71bb00ee0b0ae1`。

1. **策略键忽略颜色顺序**：旧 coordinator 始终拼蓝先红后的键。红先题目没有改写状态机颜色顺序，但使用了错误表行，部分条目被跳过，后面退回贪心。因此下午红先题的结果不能证明该题 DP 策略已被执行。现在按实际连续颜色/目的地分组构造键，全部 48 行逐条执行测试。
2. **自动策略污染后续题目**：旧代码把自动策略写回 ROS `cube_order_override`，第二题误认成用户手工覆盖。现在仅保存当前任务快照，不写派生值回参数；手工参数只在任务到达时读取，必须完整合法，任务途中变更不会污染正在执行的序列。
3. **失败重试吞掉未来颜色**：旧消费器遇到颜色不匹配仍递增索引。现在保留未来颜色条目，当前作业回退同色评分器。表行长度、颜色、实体存在性、重复实体、接近侧全部校验，不完整行整体回退。
4. **B 东侧退出修复没有覆盖真实生命周期**：`_clear_goal()` 已清掉 dock_pose，下午代码靠 dock_pose.yaw 识别东侧，实际仍可能直冲西侧出口。现在从当前朝向判断西侧/东侧，支持 -pi；东侧沿自身方向反向退让 0.45 米，随后交回 Nav2。西侧保留既有 gateway。真实 red4 投放朝向约 -3.103，退出 1.90 秒成功；另一东侧退出 1.80 秒成功。
5. 新增保留每轮目录与源码/配置哈希的运行脚本，以及独立证据审核。它区分功能完成与 <300 秒，还核对真实 pick 和 delivery_truth 的颜色/实体序列及双 yield。遇到重试不擅自删日志凑成通过，而是要求人工时间线复核。

出生点前移保留：机器人与 AMCL 同步到 (13.2,-0.95)，双障碍保留。本轮没有改速度、安全边界、地图或机械臂物理。下午首腿 23.9 ->19.8 秒支持约 4 秒收益；不能把整轮约 27 秒变化全算到出生点。246.9/252.0 秒是不同具体实体顺序的历史成功样例，不足以证明影子模型对所有题都可靠。

本轮最终测试、仿真与提交信息见同目录审计报告，避免在此复制易过期数字。已完成高风险 `4rB_1bA`：261.4 秒，5/5、零跳过、双 yield、净空 0.1313 米，颜色及投放顺序通过审计。全部 48 题尚未证明稳定低于 300 秒。
