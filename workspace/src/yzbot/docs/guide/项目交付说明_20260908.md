# YZBot 项目交付说明

交付日期：2026-09-08。交付版本、实测结果和最终状态见下面的核验记录。

**交付定位：保留挪块布局和连续巡逻的改进版，尚不能宣称全面稳定或严格 300 秒达标。** 原 B 路段反复 abort 在本轮多次运行中没有重现，但最终 B 回归缺少障碍 2 的响应证据，且机械臂仍有偶发挂接失败。成功与失败逐轮列出。

## 1. 本次交付采用的方案

保留已经挪动物块的位置：blue4 为 **(1.40, -3.90)**，blue5 为 **(2.60, -5.80)**，托盘与相关配置同步；保留机器人出生点 **(13.20, -0.95)**。

按用户本轮确认，两个移动障碍继续使用 **continuous 连续巡逻**，没有改回触发式模式，没有删除障碍或放宽安全阈值。

没有机械地把整个仓库回退到旧日期。旧版本虽有较多历史验证，仍有蓝块取块和 C 区失败；当前选择是保留挪块布局、已回退失败候选的代码基线，并修复交付前发现的具体问题。所有原始状态先完整备份。

## 2. 这次改动解决什么

### B 区回归

旧失败日志显示 red4 已经取到，去 B 东侧泊位的路径在障碍 1 低位巡逻范围附近退让并反复失败。问题不能笼统归因为挪动蓝块。

本次修复针对东南侧出发去 B 东泊位的路线，使用两个南侧中间目标引导 Nav2 通过巡逻范围下方，保留 Nav2、碰撞监控和原有停靠验收。没有把原有单个航点失败候选直接重新启用。

几何测试检查两中间目标之间的静态碰撞体距离，以及整个巡逻范围的距离；它只证明该段候选几何，不代替实际执行验收。

### 安全余量

任务 launch 原来把安全限速器的危险/警戒距离覆盖为 0.55/1.20 米。此次恢复该节点原有的保守默认值 **0.70/1.60 米**，保持底盘尺寸、Collision Monitor 及投放容差不变。

### 连续巡逻的响应记录

原 mover 只有触发式模式会记录避让响应，切换 continuous 后常出现五块完成但响应字段为空。此次补充基于 Gazebo 真值位置及新鲜底盘速度的减速记录，要求先观察到较高速度，再在邻近区域观察到减速；初始静止、一直低速、重复时间和跨间隔旧样本不能冒充响应。

原有净空、碰撞和五块零跳过验收均保留。该记录是速度变化证据，不能独自证明所有情况下的避障因果关系或替代轨迹审查。

### 抓取挂接问题与已撤回的候选

最后一轮 B 复验出现 red2 挂接后位置偏移：回收前相对手腕的 z 从 0.03575 米变为 0.06851 米，随后回收时 x 超出原有 0.060 米携带窗口。系统安全释放并换取同色 red5，最终完成五块，但耗时 327.8 秒且严格验收失败。

尝试过挂接前后 0.020 米位置一致性检查，单元测试通过，但实测发现它也拒绝正常沉降过程，三次重试耗尽后仍须换块。因此已完整撤回这个机械臂候选，恢复原逻辑并重新构建，候选代码及失败证据归档。交付包含已经验证的导航修复，机械臂偶发挂接失败仍是已知风险，不能凭定向通过宣称已经消除。

注意区分：

## 4. 如何启动与使用

在 Ubuntu VM 新终端执行：

```bash
source /opt/ros/humble/setup.bash
source "$HOME/dev_ws/install/setup.bash"
export ROS_DOMAIN_ID=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export FASTRTPS_DEFAULT_PROFILES_FILE="$HOME/dev_ws/install/tools_demo/share/tools_demo/config/fastdds_udp.xml"
cd "$HOME/dev_ws/src/yzbot"
```

确认旧仿真已停止后，启动云 API 模式并等待手动提交：

```bash
bash tools_demo/scripts/run_competition_api.sh \
  headless:=False generate_question:=False dashboard:=True moving_obstacle:=True
```

任务模块约 65 秒后开始启动；不能只凭时间判定就绪。另一个初始化过的终端检查：

```bash
ros2 lifecycle get /collision_monitor
ros2 control list_controllers
ros2 topic echo /competition/mission/state --once --qos-durability transient_local
```

碰撞监控应 active、控制器就绪，主日志出现 `persistent pick-place serving requests`。

生成官方练习题：

```bash
"$HOME/dev_ws/TMSCQtest_x86_x64.bin"
```

Windows 浏览器打开 `http://192.168.153.128:8080`（IP 以 VM 的 `hostname -I` 为准），粘贴题目和当轮映射规则，再点击一次“解析并下发任务”。解析通过即会启动搬运，不是只解析预览。

API 模型保持 `qwen3.8-max`。密钥保留在 VM 仓库外的私有环境中，本交付文件、源代码包和备份不复制该私有环境。此次交付验证没有额外调用云 API。

取消整轮：

```bash
ros2 topic pub --once /competition/mission/cancel std_msgs/msg/Bool '{data: true}'
```

取消可能释放当前物块。正常停止用主系统原终端 `Ctrl+C`，等待子进程退出；下一轮完整重启仿真以复原物块。人工驾驶从 `/cmd_vel_nav` 进入安全链，不直发 `/cmd_vel_safe`。

完整操作请打开 VM 桌面的 **ROS2竞赛系统命令手册.html**，或电脑工作区 `manual-20260906/ROS2竞赛系统命令手册.html`。CoStudio 的 coBridge 原生路径和 rosbridge 路径不能混接；Windows 面板/字段转换仍以手册中的待验收状态为准。
