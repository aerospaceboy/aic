# 比赛拍摄准备与流程

更新：2026-09-22。对应修复后的 `Start-CompetitionVideo.ps1`。

## 一条启动命令

在 **Windows 主机的 PowerShell** 执行（不要粘贴到 Ubuntu 终端）：

```powershell
& ".\Start-CompetitionVideo.ps1"
```

脚本已兼容 Windows PowerShell 5.1 和 PowerShell 7。旧问题出在 SSH 命令引号丢失；已改用 PuTTY `-m` 命令文件，官方出题程序不需更换。

执行顺序：

1. 输入**本轮真实映射规则**，例如 x/y 对应的颜色、数量到区域的映射。脚本不替你假设正式规则。
   练习示例：`x代表红色,y代表蓝色,数量大于等于3的去A区,其他颜色去C区`。正式比赛以给定映射为准。
2. 重启 VM 比赛系统，打开 Gazebo、RViz、coBridge、相机、云 API 解析器、SLAM 证据节点及备用网页。
3. 等待 `MANUAL_PROBLEM_MODE=PASS`；这个门槛现在包含 Nav2 核心节点 active、安全链 active、桥接端口和网页接口可用。
4. 调整显示窗口，开始录制。**停留在“按回车现场出题”的提示，不要提前按。**
5. 正式开始时按回车：运行官方出题程序一次、保存原始题目、发布一次、调用云 API 独立解题并验算，成功后机器人自动执行。
6. 终端会显示本题 `API_PARSE=PASS`、模型名、数量与颜色顺序，再持续显示进度和墙钟时间。失败会明确报错，不会把 HTTP 接收成功当作解题成功，也不会自动重发。

**不要在已有搬运任务执行中重跑完整启动命令。** 它会重置当前场景。若只想排查出题，在非正式录制时运行：

```powershell
& ".\Start-CompetitionVideo.ps1" -GeneratorOnly
```

这个模式只显示一道练习题，不启动比赛、不发布、不调用 API。该题不可拿来冒充正式开始后的随机出题。

只检查 SSH/Python 链路：加 `-CheckOnly`。只启动全套界面、不出题：加 `-PrepareOnly`。

## 拍摄前准备

### 设备与 VM

- 启动 Ubuntu VM，登录 `ros` 的**图形桌面**。不要仅停在登录画面；录制期间不要退出桌面会话、暂停 VM 或关闭 VM。
- 检查主机剩余录制空间、电源、网络。关掉会明显抢占 CPU/GPU 的其他工作；不要在比赛中构建项目或运行回归批次。
- 当前 IP 为 `192.168.153.128`。如果改变，在 VM 执行 `hostname -I`，命令加 `-VmAddress 新IP`。
- API 私有凭据保留在 VM 的 `~/.config/yzbot/llm.env`，不要在录屏中打开该文件。当前模型沿用分支配置 `qwen3.7-plus`，不是本轮临时改用的示例模型。
- 视频启动将 Gazebo GUI 刷新限制为 15 Hz，以降低虚拟机渲染负载；这不是修改物理仿真速度，不应加速视频。
- 一键脚本不会启动录屏软件，也不会自动保存视频。

### 画面布局

- **Gazebo 与 CoStudio 同时可见**：Gazebo 显示完整场景、机器人、货物、A/B/C 区和两个移动障碍；CoStudio 显示题目、模型解析、数量、颜色顺序、目标区域、两路相机、路径、任务进度及机械臂状态。
- CoStudio 连接方式：打开连接 → **coScene WebSocket** → `ws://192.168.153.128:21274`；布局选 **YZBot-20260921**。如果软件启动后没有自动连接，先手动连上，再按终端回车。
- 使用**实时模式**；不要点击“开始演示”。无题目时应显示等待，不能用演示数据补齐画面。
- 将题目面板拉高，保证题干、映射和解析后的顺序清晰可读；必要时滚动展示完整题目，再回到能看见主要状态的布局。
- 左侧为底盘前视相机，右侧为腕部 RGB-D 相机。两路应是不同视角。
- RViz 用于展示路径/定位。独立 SLAM 地图话题为 `/competition/slam/map`，可在 RViz 增加 Map 显示并绑定该话题；Nav2 默认仍使用预建地图。不要将预建地图称为现场实时建图结果。
- 3D 面板自动注册导航点击话题可能出现 `not whitelisted`，这是桥接拒绝控制发布，不等于图像或状态断连。不要为消除提示放开底盘控制权限。

## 录制流程

### 1. 准备画面

先完成系统启动与窗口调整。显示机器人初始状态、场景完整性及两块持续移动的障碍物，确认题目面板没有旧任务、机器人空闲。

可以进行一次单独的试录，检查文字能否读清、机械臂动作是否遮挡、两个画面是否同帧可见。试录不是正式比赛轮次。

### 2. 开始计时并现场出题

按当前赛区/裁判流程申请开始。开始录像与正式计时后，在 PowerShell 的等待提示处按回车。

保留终端输出中的官方原题和本轮映射，随后展示 CoStudio 的解析结果：本轮任务编号、模型名、解析成功、数量、目标区及颜色抓取顺序。不要手工改成预设答案，不要因为随机题不满意而重抽。

本地计时从**调用出题程序前**开始，包含生成、校验、API 等待与运动；裁判开始口令到 SSH 调用之间仍有额外开销，所以**裁判计时/完整视频墙钟是最终依据**。CoStudio 既有任务 `elapsed_sec` 是任务运动口径，不能拿它替代整场五分钟计时。

### 3. 连续展示作业

保持仿真与可视化同时可见，记录：前往目标 → 识别 → 抓取 → 搬运 → 避障 → 指定区域放置，以及面板逐块进度更新。

颜色顺序必须符合本轮题目/规则；同色具体实体可以由策略选择。不要人工拖动物块、遥控底盘或通过其他终端再次发题。

画面尽量保持连续，建议不剪掉失败、等待和恢复过程、不倍速。这是保证证据可核对的拍摄建议；具体视频格式、剪辑要求以赛区正式通知为准。

### 4. 结束与保留证据

展示第五块投放后的实际画面和终态：`completed=5`、`skipped=0`，核对放置区域及避障结果。拍到最终状态后再停止录像。

若到 300 秒仍未完成，按裁判规定结束比赛；脚本会提示超时，其后输出只用于诊断，不能算作限时成绩。脚本不会在超时瞬间擅自操作机器人或删除失败记录。

保留原视频、该轮任务编号、启动日志和终态 JSON。剪辑版如有需要，另存，不覆盖原片。

## 规则依据与建议的区别

本工作区《大模型技术创新赛比赛规则2026.pdf》记载：

- 第 3 页：操作视角需同时可视化比赛数据和仿真界面。
- 第 4 页：可赛前启动系统、调整窗口；比赛一轮，限时五分钟；开始后现场随机出题，由大模型答题。
- 第 5 页：线上比赛采用双机位，固定机位展示现场，另一机位电脑录屏；分辨率建议 1080P 及以上。省赛提交要求依赛区通知。
- 第 6 页：展示系统加载、模型解析、抓取放置、动态避障和状态反馈等评分内容。

因此，**线上比赛不能默认只有电脑录屏就够了**；应准备固定手机/相机机位和电脑录屏。具体提交容器、时长、片头、成员出镜或口播要求，在上述文件中没有统一规定，不在这里擅自编造。

## 迁移到另一台主机

仓库模板为 `tools_demo/scripts/Start-CompetitionVideo.ps1`，复制到主机工作目录再执行。现有主机已配置脚本可直接运行，不要用未配置模板覆盖它。

模板连接信息由私有环境提供：`YZBOT_VM_HOST`、`YZBOT_VM_USER`、`YZBOT_VM_HOST_KEY`、`YZBOT_VM_PASSWORD`、`YZBOT_PLINK`（plink.exe 路径）和 `YZBOT_COSTUDIO`（coStudio.exe 路径）。先核对 VM 主机指纹，使用本机凭据设置；不要把密码写入库内配置或录屏。模板默认 VM 用户的工作区为 `~/dev_ws`，源码为 `~/dev_ws/src/yzbot`，ROS 为 Humble。VM 必须先完成依赖安装与构建，并设置仓库外 LLM 环境。

`-AutoStart` 跳过开始录制前的回车等待，仅适合无人值守练习；正式录制使用默认交互模式。
