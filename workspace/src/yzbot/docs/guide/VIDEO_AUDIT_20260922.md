## 结论

原命令所指向的脚本已修复，可继续使用同一条命令。问题根因是 Windows PowerShell 5.1 经 plink 传递嵌套 Python 命令时丢失引号，远端 Bash 在 `base64.b64decode` 附近报语法错误；官方出题程序本身正常。

当前完整试跑：4 红到 A、1 蓝到 C，真实 API 独立解题，5/5、零跳过。出题程序调用前至终态观察的墙钟为 **241.807 秒**；任务自身计时 **233.2 秒**；模型调用 **7.733 秒**。这是一次当前版本成功样本，不代表所有题目都达标，也不是已提交的正式比赛成绩。

## 本轮修复

1. Windows SSH 调用改为 PuTTY `-m` 临时命令文件，保留引号与中文，兼容 PowerShell 5.1/7；使用 UTF-8 BOM 保存 PowerShell 脚本。新增只检查、仅出题、仅准备模式及控制台记录。库内通用模板从环境读取连接配置，本机已配置脚本留在工作区。
2. 新增 `video_submit.py`：调用官方随机出题程序、保留原题、校验映射、只提交一次、按当前 request/task ID 等待真实 API 解析证据。拒绝旧轮次、非空闲场景和陈旧仿真数据，不将 HTTP 成功或旧题解析成功误当成本题成功。
3. 网页状态接口保留 `/competition/task/parse_result`，脚本可以核对本轮模型、来源、顺序与数量。
4. 原问题解题 API 将规则引擎算好的候选答案发给模型并要求原样返回，实际上更接近复核。本轮移除候选答案，改由模型根据原题和映射独立解题，之后仍保留本地严格验算及必须使用 LLM 的要求。
5. 首次真实联调揭示旧启动门槛遗漏 Nav2 生命周期：碰撞监控 active 时，controller_server 仍可能配置失败，bt_navigator 未激活，但旧脚本报告启动成功。已加入 controller_server、planner_server、bt_navigator 全 active 检查、桥接存活与端口/HTTP 探测，未就绪禁止出题。
6. 视频模式启用独立 SLAM 证据节点，并延后到启动约 100 秒，避开 Nav2 集中启动；GUI 使用 15 Hz 降低渲染负担。延迟是负载缓解措施，不宣称已根治 DDS 生命周期偶发故障。增加图形桌面 Xauthority 自动发现。

## 项目审查与边界

- 挪块后布局保留：blue4=(1.4,-3.9)、blue5=(2.6,-5.8)，十个物块最小间距约 2.247m。两个障碍仍为 continuous，Y 中心 -0.35、振幅 0.45。未改布局或安全参数。
- 当前任务策略 `allow_skips=False`，有界恢复失败时应明确失败；不能据此声称不会发生抓取/导航故障。
- 当前分支模型是 `qwen3.7-plus`，本轮沿用，没有擅自改成历史 flash 示例。密钥保留在仓库外私有环境文件；模板、证据与文档不含 API 密钥。
- CoStudio 原生连接为 coScene WebSocket / 21274。已有布局与双路摄像头用于实际状态，不用演示模式。3D 控制话题被白名单拒绝不等于数据断连，不能为清除提示放开底盘控制。
- 导航仍使用预建地图；独立 Cartographer SLAM 已运行，但不能把 Nav2 的预建地图称为实时建图。录制前须确认所展示的地图话题。
- 已有 GUI 默认刷新改动及旧的未跟踪交接文档完整保留，不混入本轮提交。
- 本轮启动没有运行独立 `run_acceptance` 验收器；终态、逐块记录与避障遥测均已保留，但不伪造 `CASE_ACCEPTED=true`。全面比赛评分还需独立真值/规则验收与视频核对。
- 没有重跑 48 题，也没有证明跨题目、跨障碍相位或冷启动都稳定。旧成绩属于其对应提交。首次启动失败及两项风格失败均不隐去。

## 后续优先级

1. 先按随附流程试录，检查 Gazebo/CoStudio 同屏、完整题干、数量顺序、两路视频、SLAM 显示及固定机位。正式开始前不运行出题、不提交练习答案。
2. 如再发生启动超时，先看 controller_server、planner_server、bt_navigator 生命周期与 launch.log；新脚本会阻止发题。不要直接绕过检查。后续针对启动故障做冷启动多次验证，避免立即扩大成 48 题长测。
