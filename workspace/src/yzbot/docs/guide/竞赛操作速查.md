## 每个 VM 终端先执行

```bash
source /opt/ros/humble/setup.bash
source "$HOME/dev_ws/install/setup.bash"
export ROS_DOMAIN_ID=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export FASTRTPS_DEFAULT_PROFILES_FILE="$HOME/dev_ws/install/tools_demo/share/tools_demo/config/fastdds_udp.xml"
cd "$HOME/dev_ws/src/yzbot"
```

## 正常比赛操作

1. 确认旧系统已停。`pgrep -a -x gzserver` 有输出时先查原启动终端，不叠加启动。
2. **终端 A** 启动 API 模式，等待你发题：

```bash
bash tools_demo/scripts/run_competition_api.sh \
  headless:=False generate_question:=False dashboard:=True moving_obstacle:=True
```

3. **终端 B** 检查就绪：

```bash
ros2 lifecycle get /collision_monitor
ros2 control list_controllers
ros2 topic echo /competition/mission/state --once --qos-durability transient_local
```

任务模块约 65 秒才开始启动；需要碰撞监控 active、控制器就绪，主日志有 `persistent pick-place serving requests`。不要只凭等待时间发题。

4. 生成官方应用题：

```bash
"$HOME/dev_ws/TMSCQtest_x86_x64.bin"
```

5. 打开网页：VM 用 `http://127.0.0.1:8080`；Windows 用 `http://192.168.153.128:8080`，IP 以 `hostname -I` 为准。
6. 粘贴完整题目，核对本轮映射规则，点击一次“解析并下发任务”。**解析通过就会自动开始搬运。**
7. 看 `llm_status` 的 source=llm、available=true，再看计划与任务。网页 accepted 只说明收到了请求。

```bash
ros2 topic echo /competition/task/llm_status --qos-durability transient_local
```

## 自己指定直接搬运任务

只在系统空闲、新场景中发；这是直接指令，不是官方算术出题：

```bash
ros2 topic pub --once --qos-reliability reliable --qos-durability transient_local \
  /competition/task/question std_msgs/msg/String \
  "{data: 'Move 4 red cubes to zone B and 1 blue cube to zone A.'}"
```

## 取消和停止

取消整轮（可能释放当前物块，不是保持姿态暂停）：

```bash
ros2 topic pub --once /competition/mission/cancel std_msgs/msg/Bool '{data: true}'
```

停止主系统：原终端 A 按 `Ctrl+C`，等待退出，再停桥接/录包/其他发布器。下一轮完整重启仿真，恢复机器人及物块。网页刷新、只关 Gazebo、重复原题，都不是整轮复位。

**人工驾驶先看主手册第 6 节：从 `/cmd_vel_nav` 进入，禁止直发 `/cmd_vel_safe`。`clean_launch.sh` 会清理并自动启动非 API 系统，不用它当停止按钮。**

单题运动基准用 `run_ordered_case.sh`，不经过 API；5/5 与完整比赛低于 300 秒是两种结论，不混报。
