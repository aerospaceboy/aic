## 1. 项目概述

本项目面向月球仓储基地仿真分拣场景，基于 ROS 2 Humble、Gazebo
Classic、Nav2、Cartographer、MoveIt 2、RGB-D 视觉和 OpenAI
兼容大模型接口，实现随机题目解析、红蓝方块识别、多动态障碍物避障、
六自由度机械臂抓取、移动搬运、A/B/C 分区投放和浏览器实时评分面板。

一轮竞赛固定生成 5 个目标方块，系统严格按照大模型输出顺序执行。
只有 5 个方块全部完成、零跳过、真实大模型解析成功、全部动态障碍物
均被观测且未检测到碰撞时，自动验收才返回 PASS。

## 2. 系统架构

系统分为七层：

1. 出题层：生成包含颜色、数量、顺序和目标区域的自然语言题目。
2. 大模型层：调用 OpenAI 兼容接口，要求模型输出严格 JSON。
3. 协议层：交叉验证模型结果与题面，拒绝幻觉、漏项和超量任务。
4. 感知层：通过 HSV 连通域、深度中值、相机内参和 TF 生成三维目标。
5. 导航层：Nav2 使用固定比赛地图执行任务，同时 Cartographer 在隔离
   话题构建实时 SLAM 地图作为比赛证据。
6. 操作层：MoveIt 规划机械臂轨迹，LinkAttacher 模拟可靠夹持，
   Gazebo 实体真值核验最终落区。
7. 展示与验收层：浏览器面板显示题目、模型来源、顺序、数量、识别结果、
   路径、进度、夹具、多障碍物避障和剩余时间。

## 3. 大模型任务解析

系统默认调用：

```text
http://localhost:8081/v1/chat/completions
```

模型输出必须符合以下结构：

```json
{
  "schema_version": "1.0",
  "items": [
    {"color": "red", "count": 2, "target_zone": "A"},
    {"color": "blue", "count": 3, "target_zone": "C"}
  ]
}
```

解析器验证颜色、数量、区域、总数和执行顺序，并将模型结果与题面规则解析
结果交叉核对。竞赛模式下，模型不可用、超时、输出非法或内容与题目不一致
都会拒绝启动该轮任务，不会使用规则结果冒充大模型成功。

`/competition/task/llm_status` 实时发布模型名称、服务地址、耗时、可用性
和解析来源，供裁判面板及自动验收核查。

## 4. 视觉识别

RGB-D 识别流程为：

1. 对 RGB 图像转换 HSV；
2. 分别提取红色双区间和蓝色区间；
3. 形态学去噪并计算连通域；
4. 取目标区域深度中值；
5. 使用相机内参投影到三维相机坐标；
6. 根据图像时间戳查询 TF 并转换到 `base_link`；
7. 发布目标颜色、像素区域、深度和三维坐标。

评分面板显示当前识别目标总数及红蓝目标数量。

## 5. 导航、SLAM 与动态障碍物

Nav2 使用静态比赛地图保证五分钟任务的可重复性。Cartographer 同时在
`/competition/slam/map` 构建实时地图，其 TF 和地图话题与 Nav2 隔离，
避免影响稳定导航。

场景包含三个独立可碰撞的移动障碍物：两个 0.06×0.80×0.60 m 板子在
出生点走廊 x=13.4 处沿 y 反相位摆动（周期 12 s），以及一个半径 0.18 m
圆柱以 20 s 周期横穿主走廊。静态地图把各移动障碍物的完整扫带标成静态 ghost，
使全局路径绕开移动扫带，避免底盘高速穿越薄板子（激光雷达 0.38 m 内存在盲区）。
避障监视器读取 `/odom` 和各 Gazebo 障碍物真值，持续计算机器人与障碍物的
最小物理间距。一旦检测到几何碰撞，本轮验收永久标记失败。

## 6. 抓取、搬运与投放

每个目标依次执行：

1. 导航至对应颜色取料区；
2. 将腕部 RGB-D 相机移动到扫描位姿；
3. 选择可达的指定颜色目标；
4. MoveIt 执行预抓取、下降、夹持和抬升；
5. LinkAttacher 建立固定关节并核验相对漂移；
6. 沿安全离架路径驶出取料区；
7. 导航到题目指定 A/B/C 区；
8. MoveIt 执行下降、释放、抬升和复位；
9. 查询 Gazebo 实体真值，确认方块位于指定区域。

## 7. 五分钟约束

任务层内部预算为 295 秒，外部验收上限为 300 秒。导航速度、机械臂速度、
加速度、笛卡尔段时长和夹具时长均采用竞赛调优参数。

自动验收成功条件为：

```text
state == completed
completed == total == 5
skipped == 0
LLM source == llm
obstacles_seen >= 2
collision_detected == false
avoidance safe == true
elapsed_sec <= 300
```

## 8. 可视化与标准话题

面板显示以下评分信息：

- 当前自然语言题目和大模型名称；
- 红蓝资源数量和逐块抓取顺序；
- 当前方块、目标区域和任务阶段；
- Nav2 实时路径及机器人位置；
- RGB-D 识别目标数量；
- 机械臂夹具状态；
- 动态障碍物数量及安全状态；
- 完成数量、总数和比赛剩余时间。

核心话题均使用 `/competition/...` 命名空间，并以标准 ROS 2
`std_msgs`、`nav_msgs`、`sensor_msgs` 和 `geometry_msgs` 类型发布。

## 9. 创新点

1. 大模型输出与确定性语义解析双重校验，避免幻觉直接控制机器人。
2. Nav2 固定地图与隔离 Cartographer 实时 SLAM 证据并行运行。
3. 使用 RGB-D 时间同步和时间戳 TF 生成可抓取三维目标。
4. MoveIt 真实执行、LinkAttacher 生命周期与 Gazebo 真值三层验证。
5. 自动验收拒绝部分完成、规则冒充模型和未验证避障的假 PASS。
6. 浏览器面板以裁判评分项为信息架构，而不是仅显示调试日志。

## 10. 构建与运行

```bash
cd ~/dev_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
ros2 launch tools_demo competition_system.launch.py
```

比赛前必须先启动并预热 OpenAI 兼容模型服务。看到以下输出才表示
整套系统满足启动契约：

```text
COMPETITION_ACCEPTANCE=PASS
```

五分钟端到端验收命令见 `docs/competition_operator_guide.md`。
