# 原地转向与 blue_3 固定绕行复修（2026-10-21）

## 上一版结论的纠正

用户再次提供截图后，复核发现两项判断范围不足：

1. 出生段检查了接近等待点的朝向，却没有检查停下后的准入等待阶段。
   旧 `spawn-corridor-20261021/round5` 的停车样本中，实际角速度最大
   0.63647 rad/s，直接转向指令最大 0.63685 rad/s。不能把整轮 5/5 或
   “接近段没有转圈”当作等待点原地转向已消除的证据。
2. blue_3 上一版仍先生成用于补齐两份响应的固定穿行，响应取得后才取消。
   因此仍会出现先向东再斜向返回的三角形。旧轮在 x=0.772 才取消 EAST，
   虽未走完折返，用户指出的额外路线仍然存在。

用户本轮明确选择：**彻底取消人为绕行，真实记录指标**。两份避障响应的验收
规则保留；没有自然发生时显示未完成，不通过安排额外运动来补齐。

## 修改

### blue_3 路线生成

`current_pickup_guides()` 从生成源头去掉 WEST→EAST→WEST 补演。
正常北侧接近继续通过北、西南两个巡逻外围引导点；到南侧后直接前往抓取入口，
不因缺少响应计数而转向东侧。已在南侧的起点同样不生成穿行。调度耗时估算
共用同一函数，因此不再为已经删除的路线计费。

外围安全引导不删除。若起点本来就在巡逻区东侧中段，仍可使用原南侧安全点
作单向向西转移；不额外添加西→东的补演段。该分支与本轮从 A 区经西侧接近
的路线分开测试。原有避障证明验证、限速器、碰撞保护和验收判断均未放宽。

### 等待点原地转向

旧控制器追踪点坐标：接近终点后，厘米级横向残差仍对应一个非零目标方位；
到位停车后，准入控制器再旋转到向西通行方向。

新控制器在移动中并入固定西行通道。目标朝向根据横向偏差收敛到 π，不再追着
近处点的方位绕转。到达判定同时要求：位置误差 ≤0.03 m、朝向误差 ≤0.04 rad，
之后还需实际静止并通过原 ≤0.04 m 位置证明，才进入准入等待。

第二轮又复现保护检查失败后立即交回 Nav2，随后再次出现停车转向。最终正常
路线在墙角引导完成、实际静止时就接管整个等待点接近段（不超过 3.1 m），
不再先发出这一段的 Nav2 点追踪再取消。每步仍检查同一条独立证明的通道，
没有用扩大安全距离容差来维持控制权；临时检查失败立即停车并重验，持续阻挡
达到有界截止时间才交回原导航目标。距离增加后截止时间为 16 s，穿越准入的
安全距离与等待窗口不变。

速度上限仍为 0.35 m/s，角速度上限 0.60 rad/s，接近已验证区域的横向边缘时
进一步降低平移速度；每步仍验证静态车体通道、
实时地图与定位有效性，取消原 Nav2 动作仍等待终态。地图失效或超时停止并交回
原目标，用户取消优先。真实对齐不足时的安全约束保留，未强行关闭安全对准分支。
