# YZBot 大模型技术创新赛项目说明与实施总结

## 1. 项目概述

YZBot 是一个基于 ROS 2 Humble 的移动操作机器人仿真项目。本项目以“全球校园人工智能算法精英大赛·算法应用赛·大模型技术创新赛”为目标，面向月球仓储基地中的红蓝货物智能分拣、搬运和放置任务。

项目在 Gazebo Classic 中搭建了由差速移动底盘、六轴机械臂、夹爪、二维激光雷达、RGB 相机和 RGB-D 相机组成的机器人模型，并集成以下功能：

- 使用 Gazebo 进行机器人和场景物理仿真；
- 使用 ros2_control 控制机械臂和夹爪；
- 使用 MoveIt 2 完成机械臂运动规划和轨迹执行；
- 使用 Nav2 完成地图定位和移动底盘导航；
- 使用 Cartographer 或 RTAB-Map 进行建图实验；
- 使用 Gazebo LinkAttacher 服务模拟物体抓取和释放；
- 使用 llama.cpp 运行本地 Qwen 模型，并通过 ROS 2 话题发布模型回复。

项目当前已经完成各基础模块的搭建，形成了“大模型 + ROS 2 + 计算机视觉 + Nav2 + MoveIt 2 + Gazebo”的系统基础。最终目标是在 5 分钟比赛时间内，根据随机题目规定的货物数量、颜色、抓取顺序和放置区域，自动完成题目解析、目标识别、自主导航、避障、抓取、搬运、放置、状态播报与可视化。

## 2. 竞赛目标与任务定义

### 2.1 应用背景

比赛场景设定为月球仓储基地。机器人需要代替人员在仓储环境中完成货物识别、分拣、搬运和入区放置，以验证大模型、计算机视觉、自主导航和智能机器人技术在深空后勤场景中的融合应用。

比赛平台中的主要作业对象为：

- 红色立方体包裹；
- 蓝色立方体包裹；
- A、B、C 三个指定放置区域；
- 固定或可移动障碍物；
- 标准移动底盘和六自由度机械臂。

本项目 `room.world` 已包含红、蓝方块及 A/B/C 放置区域，与赛题目标场景相对应。

### 2.2 总体目标

项目需要构建一套完整的智能仓储作业系统，使机器人能够：

1. 从出题程序获取随机任务题目和抓取顺序；
2. 使用本地大模型理解自然语言题目；
3. 提取红蓝货物数量、抓取顺序和对应放置区域；
4. 将解析结果发布到标准 ROS 2 话题；
5. 使用视觉识别货物颜色并估计其空间位置；
6. 根据任务顺序选择当前目标；
7. 使用 Nav2 规划路径并自主避障；
8. 移动到机械臂可抓取的位置；
9. 使用 MoveIt 2 规划机械臂抓取动作；
10. 抓取并验证货物状态；
11. 将货物搬运到指定 A、B 或 C 区域；
12. 放置货物并验证释放状态；
13. 重复执行，直到完成全部任务；
14. 实时播报任务状态；
15. 在可视化面板中展示题目、解析结果、路径、识别结果、进度和机器人状态。

### 2.3 完整比赛任务链

```text
出题程序
    ↓
随机自然语言题目 + 随机抓取顺序
    ↓
本地大模型解析
    ↓
结构化任务计划
    ↓
视觉识别红/蓝货物并定位
    ↓
任务调度器选择当前货物
    ↓
Nav2 导航并避障
    ↓
MoveIt 2 规划抓取
    ↓
夹爪闭合 + LinkAttacher 吸附
    ↓
Nav2 搬运至 A/B/C 区
    ↓
MoveIt 2 放置 + LinkAttacher 释放
    ↓
状态反馈、结果验证、执行下一个任务
```

### 2.4 比赛关键约束

| 约束 | 要求 |
| --- | --- |
| 比赛轮次 | 1 轮 |
| 时间限制 | 5 分钟 |
| 抓取规则 | 必须严格按照随机题目给出的顺序 |
| 放置规则 | 必须放置到题目指定区域 |
| 大模型 | 必须用于题目理解和任务解析 |

| 比赛展示 | 同时展示仿真界面和数据可视化界面 |

## 4. 项目组成

项目源码位于：

```text
~/dev_ws/src/yzbot
```

主要目录如下：

```text
yzbot/
├── mybot_description/       # 机器人 URDF/Xacro、传感器模型和 Gazebo 世界
├── mybot/                   # MoveIt、ros2_control 配置及启动文件
├── bot_navigation/          # Nav2、Cartographer、地图和 RViz 配置
├── IFRA_LinkAttacher/       # Gazebo 抓取/释放插件及服务接口
├── tools_demo/              # llama.cpp 对话及 ROS 2 话题发布程序
├── cube_control.sh          # 方块吸附/释放辅助脚本
├── my_send_goal.sh          # 机械臂关节轨迹示例
├── pick_on.sh               # 夹爪动作示例
├── pick_off.sh              # 夹爪动作示例
└── send_goal_pick.sh        # 机械臂和夹爪组合轨迹示例
```

### 4.1 mybot_description

该功能包负责机器人和仿真环境的描述，主要包含：

- 差速移动底盘；
- 六轴机械臂；
- 单自由度夹爪；
- 二维激光雷达；
- RGB 相机；
- 安装在机械臂末端的 RGB-D 相机；
- `room.world`、`cloister.world` 和 `box.world` 等 Gazebo 场景。

组合机器人模型入口为：

```text
mybot_description/urdf/originbot_with_rgbd_gazebo_arm.xacro
```

### 4.2 mybot

该功能包负责机械臂运动规划和控制，主要包含：

- MoveIt SRDF；
- KDL 运动学求解器配置；
- 机械臂和夹爪控制器配置；
- 关节限制和初始位置；
- Gazebo、MoveGroup 和 RViz 启动文件。

机械臂使用以下控制器：

- `arm_controller`：控制 `joint1` 至 `joint6`；
- `gripper_controller`：控制 `finger_joint1`；
- `joint_state_broadcaster`：发布 `/joint_states`。

### 4.3 bot_navigation

该功能包负责移动底盘的定位、建图和导航，主要包含：

- Nav2 参数；
- AMCL 定位参数；
- Cartographer 配置；
- RTAB-Map 启动文件；
- 栅格地图；
- 导航和建图 RViz 配置。

导航使用的核心数据为：

```text
/scan       激光雷达数据
/odom       底盘里程计
/cmd_vel    底盘速度指令
/tf         坐标变换
/map        栅格地图
```

### 4.4 IFRA_LinkAttacher

该模块是第三方 Gazebo 插件，通过在两个 Gazebo link 之间创建临时固定关节来模拟抓取。

提供以下服务：

```text
/ATTACHLINK    吸附物体
/DETACHLINK    释放物体
```

默认的 `room.world` 已加载该插件，因此可以对场景中的红色和蓝色方块进行吸附或释放。

### 4.5 tools_demo

该功能包用于连接本地 llama.cpp 服务，包含：

- 普通终端对话程序 `chat_interactive.py`；
- ROS 2 对话程序 `chat_interactive_ros.py`；
- `chat` 和 `chat_ros` 两个 ROS 2 可执行入口。

`chat_ros` 会将大模型回复作为 `std_msgs/String` 发布到：

```text
/llama_command
```

当前项目尚未实现 `/llama_command` 的任务执行订阅节点，因此该话题目前主要用于演示大模型与 ROS 2 的通信。

## 5. 系统工作流程

完整系统的数据流如下：

```text
Gazebo
├── robot_state_publisher ───────────────→ /tf、/tf_static
├── gazebo_ros_diff_drive ← /cmd_vel ───→ /odom
├── Gazebo 激光雷达 ─────────────────────→ /scan
├── Gazebo 相机 ─────────────────────────→ 图像/深度话题
├── gazebo_ros2_control
│   ├── arm_controller
│   ├── gripper_controller
│   └── joint_state_broadcaster ─────────→ /joint_states
└── LinkAttacher ────────────────────────→ 抓取/释放服务

Nav2
├── 输入：/map、/scan、/odom、TF
└── 输出：/cmd_vel

MoveIt 2
├── 输入：机器人模型、/joint_states、TF
└── 输出：机械臂和夹爪轨迹 Action

llama.cpp
└── tools_demo ──────────────────────────→ /llama_command
```

### 11.2 结构化大模型任务

大模型不应直接生成可执行 shell 命令或任意 ROS 指令，而应将自然语言题目转换成可校验的任务数据。例如：

```json
{
  "task_id": "round_1",
  "items": [
    {
      "sequence": 1,
      "color": "blue",
      "target_zone": "A"
    },
    {
      "sequence": 2,
      "color": "red",
      "target_zone": "C"
    }
  ],
  "counts": {
    "red": 1,
    "blue": 1
  }
}
```

解析节点需要执行以下校验：

- `color` 只能为 `red` 或 `blue`；
- `target_zone` 只能为 `A`、`B` 或 `C`；
- 数量必须与任务列表一致；
- `sequence` 必须连续且不能重复；
- 货物总数不能超过场景中的可用数量；
- 大模型输出异常时必须重试或切换到安全失败状态。

### 11.3 比赛任务状态机

建议使用确定性的 ROS 2 Action/状态机编排比赛任务：

```text
WAIT_TASK
    ↓
PARSE_TASK
    ↓
DETECT_CARGO
    ↓
SELECT_NEXT_ITEM
    ↓
NAVIGATE_TO_CARGO
    ↓
ALIGN_FOR_GRASP
    ↓
PLAN_AND_GRASP
    ↓
VERIFY_GRASP
    ↓
NAVIGATE_TO_ZONE
    ↓
PLAN_AND_PLACE
    ↓
VERIFY_PLACE
    ├── 还有任务 → SELECT_NEXT_ITEM
    └── 全部完成 → FINISHED
```

任何关键步骤失败后应进入 `RECOVERY`，根据失败类型执行重新识别、重新导航、重新规划、再次抓取或安全结束，避免节点因一次失败永久阻塞。

### 11.4 建议的 ROS 2 比赛数据接口

最终话题名称和消息类型必须服从组委会发布的正式接口。正式接口公布前，可以按以下逻辑设计内部消息：

| 建议话题 | 内容 |
| --- | --- |
| `/competition/task_text` | 出题程序生成的原始题目 |
| `/competition/task_plan` | 大模型解析后的结构化任务 |
| `/competition/detections` | 红蓝货物类别、置信度和位姿 |
| `/competition/navigation_path` | 当前导航路径 |
| `/competition/progress` | 当前序号、已完成数和总数 |
| `/competition/work_state` | 当前工作状态 |
| `/competition/gripper_state` | 末端抓取、持有或释放状态 |
| `/competition/round_result` | 本轮完成情况和失败原因 |
| `/competition/announcement` | 文本或语音播报内容 |

任务执行节点应统一发布状态事件，避免导航、机械臂、视觉和界面分别维护互相矛盾的任务状态。

### 11.5 视觉识别与定位方案

比赛目标只有红色和蓝色立方体，可以优先采用稳定、可解释且计算量较低的视觉方案：

1. 订阅 RGB-D 相机彩色图像、深度图和相机参数；
2. 在 HSV 颜色空间分割红色和蓝色区域；
3. 通过轮廓面积、长宽比和深度有效性过滤误检；
4. 获取目标中心像素及深度；
5. 使用相机内参计算三维坐标；
6. 通过 TF2 将相机坐标转换到 `map` 或 `base_link`；
7. 发布带颜色、编号、置信度和位姿的识别结果；
8. 抓取前进行近距离二次识别和位姿修正。

该方案可以满足红蓝方块识别需求，并将大模型保留在高层任务理解位置，避免让大模型承担不稳定的像素级定位工作。

### 11.6 可视化面板目标

比赛面板至少应包含：

- 原始任务题目；
- 大模型解析后的红蓝数量；
- 严格的抓取与放置顺序；
- 当前执行第几个货物；
- 已完成数量和总进度；
- 当前识别目标及其位置；
- 机器人实时导航路径；
- 当前工作状态；
- 夹爪抓取、持有和释放状态；
- 当前轮次结果、耗时和错误信息；
- Gazebo 或 RViz 画面。

推荐将任务数据和机器人状态放在独立面板中，将地图、路径、TF 和机器人模型继续交给 RViz 显示。

### 11.7 五分钟性能目标

为了在 5 分钟内完成最多 5 个货物的抓取和放置，系统设计需要关注：

- 启动阶段自动完成节点健康检查，避免比赛开始后再排查依赖；
- 对同一区域任务进行合理路径规划，同时保持题目规定的抓取顺序；
- 机械臂使用预计算的安全姿态和笛卡尔短路径；
- 导航、识别和机械臂准备过程尽量并行，但实际动作必须通过状态机同步；
- 对抓取和放置设置明确超时，失败时快速重试；
- 记录每个阶段耗时，针对最慢环节优化；
- 在正式比赛前持续进行完整 5 分钟压力测试。

## 12. 后续扩展方向

### 12.1 总体技术路线

项目应按照“高层智能决策与底层确定性控制分离”的思路建设：

```text
自然语言输入
    ↓
大模型生成结构化任务
    ↓
任务校验与状态机
    ├── Nav2 移动到抓取位置
    ├── 感知模块确认目标
    ├── MoveIt 执行抓取
    ├── LinkAttacher 模拟持物
    ├── Nav2 移动到目标区域
    └── MoveIt 放置并 Detach
```

大模型适合负责高层任务理解和步骤规划，具体机器人动作应由经过范围校验、状态检查和失败恢复的确定性 ROS 2 节点执行。

### 12.2 可体现的创新点

1. **大模型结构化任务规划**  
   使用本地大模型完成自然语言题目的语义解析，并通过 Schema 校验、自动纠错和任务约束生成可靠的机器人任务序列。

2. **移动底盘与机械臂分层协同**  
   使用 Nav2 解决全局移动问题，使用 MoveIt 2 解决局部精确操作问题，由统一状态机完成跨系统协同。

3. **视觉、地图与任务语义融合**  
   将视觉检测结果转换到地图坐标系，使“红色货物”“蓝色货物”“A/B/C 区域”等语义对象成为可规划任务实体。

4. **仿真抓取双重验证**  
   同时结合夹爪关节状态和 LinkAttacher 吸附结果判断抓取是否成功，提高比赛过程的可重复性。

5. **面向裁判评分的数字化状态反馈**  
   将题目解析、识别、导航、抓取、放置、耗时和失败恢复统一为事件流，实现全过程可追踪、可回放和可视化。

6. **月球仓储场景扩展**  
   在标准比赛场景基础上增加月面地形元素、动态障碍和仓储设施，在不破坏标准接口的前提下提升场景设计与工程创新性。

## 13. 总结

YZBot 的明确目标是参加大模型技术创新赛，并在统一 ROS 2 仿真平台中完成月球仓储红蓝货物的智能分拣和搬运。项目已经集成移动底盘、机械臂、夹爪、传感器、Gazebo、MoveIt 2、Nav2、仿真抓取插件和本地大语言模型，具备实现比赛系统的基础条件。

当前项目的核心价值是将多个 ROS 2 子系统集中在同一个仿真环境中，为后续研究以下内容提供基础：

- 移动机器人定位与导航；
- 机械臂运动规划与控制；
- 移动操作机器人协同；
- 仿真抓取与放置；
- 本地大模型与 ROS 2 通信；
- 自然语言驱动的机器人任务规划。

下一阶段的重点不是继续增加孤立功能，而是围绕比赛评分要求打通完整闭环：随机题目输入、大模型结构化解析、红蓝货物视觉定位、严格按序导航抓取、A/B/C 区域放置、动态避障、状态播报和可视化反馈。完成该闭环并通过 5 分钟连续测试后，项目才能达到正式参赛系统的目标。
